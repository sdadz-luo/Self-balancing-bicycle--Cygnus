## 项目边界与验收

- **无人自主平台，车上不载人**（硬约束）
- **验收分三层**，逐层递进，前一层未通过不进入下一层：
  1. **静止平衡**——原地站立不倒
  2. **行驶与转向**——直线行驶、转向；**动量轮全程参与平衡**，只是与转向的
     权重随车速调度
  3. **自主导航**——**陌生园区环境**（室外、几百米尺度）自主运动到目标点，
     RDK 输出目标车速 / 航向

## 系统架构

### 三端分工

| 端 | 角色 | 职责 |
| --- | --- | --- |
| STM32G431 | 电驱 | FOC 电流环、换相、DRV8301 / MT6816 驱动、硬件保护 |
| ESP32-S3 | 下位机（控制） | 平衡环、运动控制、状态机、指令仲裁 |
| RDK X5 | 决策端 | GNSS 双天线 / 双目相机 / 激光雷达、定位融合、路径规划 |

> **术语**：本项目的「三端」指 CAN 总线上的 STM32 / ESP32 / RDK；遥控器是
> 独立第四端，经 NRF24L01 接 ESP32。「上位机」专指操作 PC，「下位机」专指
> ESP32-S3；RDK X5 称「决策端」。

### 执行器与归属

| 执行器 | 作用 | 控制方 | 失效行为 |
| --- | --- | --- | --- |
| 动量轮电机 | 左右平衡（**全程在线、运行中不许停**，低速时承担主分量） | STM32 力矩环 ← ESP32 平衡环 | 断桥臂，飞轮自然减速 |
| 摩擦驱动电机 | 前进 / 制动 | STM32 ← ESP32 速度环 | 断桥臂 |
| 总线舵机 | 前轮转向（高速时承担平衡主分量） | ESP32 串口 | 回中 |

### 整车硬件构成

| 部分 | 构成 |
| --- | --- |
| 车体 | 20 寸标准死飞，拆曲柄 / 脚踏 / 牙盘 / 链条 |
| 电驱板 | STM32G431RBT6 + DRV8301 ×2 + MT6816 ×2 |
| 控制板 | ESP32-S3 + 外接 CAN 收发器 |
| 决策端 | RDK X5 8G |
| 传感器 | GNSS 双天线 UM982 + 双目 GS130WI（含 IMU）+ 激光雷达 D800（STL27L）+ IMU HWT606 |
| 转向 / 驱动 | 总线舵机 飞特 ST-3035-C001；摩擦驱动压后轮胎 |
| 电源 | 6S 锂聚合物，5300 mAh 30C |

### 域隔离

- **控制域**（ESP32-S3 + STM32G431）在闭环内，实时、不许丢包
- **决策域**（RDK X5）输出「建议」而非命令，掉线不影响控制回路
- 传感器原始数据不往总线上发，总线上只跑规划结果与控制量
- **安全兜底不依赖无线链路，也不依赖 RDK**
- **遥控器是独立于 RDK 的控制通道**——不接入 RDK 时，全车仍可由遥控器完整控制
  （起立、行驶、转向、停车）

## 技术路线与关键决策

### 平衡：反作用轮 + 转向，增益调度

「静止靠动量轮、行驶靠转向」——与 XUAN 架构一致。但**动量轮的平衡作用全程
有效、从不退出回路**，随车速变化的只是两者的权重：

| 车速 | 谁承担主分量 |
| --- | --- |
| 0 ~ 2 m/s | **动量轮**（前轮转向不产生纠正力矩，平衡力矩 ∝ v²） |
| 2 ~ 5 m/s | 混合（转向管慢分量，动量轮管高频扰动） |
| > 5 m/s | 转向为主（不消耗动量），动量轮权重降低但**不归零** |

不存在「交班完成、动量轮下班」这一步。转向环带宽只有 2 ~ 5 Hz，高频侧倾
扰动它来不及响应，那部分只能由动量轮承担——把动量轮增益归零是**功能缺失**，
不是调参问题。交叉点（2 / 5 m/s）待 M4 实测标定。

⚠️ **工作车速 1 ~ 4 m/s（包线 5 m/s），所以「> 5 m/s 转向为主」这一档不会进入**
——转向全程只承担「混合」段的分工。若 M4 标定发现上交叉点下移到 4 m/s 以内，
舵机负载要重新评估。

### 控制算法：PID 验证，LQR 定型

平衡环的反馈律分两阶段。**控制频率、IMU 接口、CAN 指令、动量卸载与分级
降级都不变**，只替换算法：

| 阶段 | 算法 | 目的 |
| --- | --- | --- |
| 前期 | 串级 PID（横滚角速度内环 + 角度外环） | 先验证方向、增益量级、IMU 延迟与执行器响应，并为 LQR 积累模型辨识数据 |
| 后期 | LQR（状态反馈） | 用状态反馈改善多变量耦合与飞轮转速（动量卸载）的整定 |

**为什么先 PID**：参数少、物理意义直观，模型未知时也能先把车立住；直接上
LQR 会把「模型错」与「传感 / 执行链错」混在一起。**为什么最终换 LQR**：
反作用轮 + 转向是多变量系统，LQR 能把横滚、飞轮转速等状态纳入统一反馈，
比手工串级 PID 更容易在行驶 / 转向阶段整定。

**LQR 的范围**：最低限度替换平衡环（横滚 / 飞轮转速 → 动量轮力矩）；
速度环、转向环**暂保持现有结构**，有余力再逐步纳入。切换风险最小，也保留
回退到 PID 的可能。

**切换不预设硬时点**：以「PID 已把方向、增益量级、IMU 延迟与执行器响应
验证清楚，且模型辨识数据足够设计 LQR」为判据，由实测决定。切换前保留 PID
路径，LQR 未达标时可回退。LQR 的线性化模型、状态量与 Q/R 权重待 M1/M2
取得模型辨识数据后确定（见「待定事项」）。

### 车体与驱动：20 寸死飞 + 摩擦驱动

**摩擦驱动**——电机轴上的摩擦轮压在后轮胎上，沿用现成开源结构。保留原装
后轮，**不换轮组、不撑开档**，绕开了死飞 120 mm 开档与轮毂电机 135 mm 不
匹配的问题。代价是打滑（固有 0.5 ~ 2%）与轮胎损耗，故**车轮单独装霍尔做
里程计，不能复用电机编码器**。

### 动力：6S + EA90 KV105 直驱飞轮

**力矩上限只由电流决定，与母线电压无关**（`τ_max = Kt × I_esc`），所以砸电流
比升压划算得多——功率级按 100 A 设计。飞轮取 **Ø150 轮缘环**（不做实心盘：
同惯量下环省一半质量）。**θ_rec = ±3° 是唯一自由参数**，其余规格全由它推出，
飞轮需求 ∝ (Mgh × θ_rec)²，是全篇最敏感的一条。

**飞轮与电机直驱、零偏置**：工作点转速为 0，±1800 rpm 是纠偏瞬态峰值，
**没有「起转到工作转速」这一步**。每次纠偏留下净动量，必须靠车身缓慢倾斜
卸载——**这不是可选项**。

### 感知：GNSS 主导，双目为主，激光雷达补盲

- **航向来自 GNSS 双天线真北，不用磁力计**——车上 100 A 电流产生的磁场
  （20 cm 处约 100 µT）远大于地磁水平分量（约 30 µT），磁力计装了也是废数据。
  连锁收益：飞轮材料可回到碳钢，不用为非磁性让路
- **用千元内 DTOF 激光雷达（乐动 D800 / STL27L，¥576），不买 ¥2500+ 的工业档**
  （RPLIDAR S2 / 镭神 M10P 级）。三条筛选逻辑：① **三角测距原理出局**——抗光
  <1000 lux，白天直接失效，强阳光甚至可永久损坏感光芯片；② **抗光 ≥60 Klux
  是户外底线**——30 Klux 档（LD06 / D300 / N10）阳光直射下数据错乱，40 Klux
  （RPLIDAR C1）余量不足；③ **抗光同档时标称量程越远，阳光下打折后剩下的越多**
  ——25 m 的 D800 优于 12 m 的 D500 / D6，且 0.167° 角分辨率直接决定「空隙
  宽度」的分辨能力，多回波兼做玻璃幕墙检测。⚠️ 60 Klux 低于正午直射约 10 万
  lux，属**灰区**：装车后必须实测正午直射下的有效测距（见待定事项），不达标
  则升 RPLIDAR S2L（80 Klux + IP65）。**D800 无 IP 防护**，需自制防雨罩（留
  水平激光窄缝，不得用整块亚克力挡光路）
- **两个互补的感知模块**（双目 / 激光雷达），距离段与失效条件几乎不重叠
  ——任一类失效时另一类仍可用。这是刻意的**失效模式冗余**，不是堆料。
  ⚠️ **代价明说：雨雾格无人补**——原方案的毫米波是唯一能穿透雨雾的模块，
  删除理由是 C4001 属人体存在检测模块、单目标语义输出，对静止障碍的可靠性
  存疑（装在移动平台上是否有效为未验证项）；雨雾下三种传感器会同时退化，
  这是**已接受的缺口**，若未来要补应选多目标 / 原始点云输出的真雷达模块
- **双目是主传感器，但不是唯一**。它天然免疫侧倾（深度是逐像素算的，与车体
  姿态无关），这是它相对 2D 雷达的根本优势；代价是逆光与无纹理场景会失效，
  由激光雷达补
- **双目不能只当点云源用**：曝光策略 + stereonet 置信度加权 + BPU 语义检测，
  三项软件增强是缓解逆光 / 无纹理失效的唯一低成本手段（详见参数 5.1）。
  绕行的空隙宽度以双目为主来源、激光雷达为第二来源

### 导航：无图模式为主

**定位**：GNSS 星基 PPP + 双天线真北 → 双 EKF，不需要基站、不需要网络、
不需要建图环节。**不用高精地图**——已有卫星图与矢量路网作全局先验（软约束：
别穿草坪、别穿楼），实时感知作硬避障。

**为什么可行**：园区级场景（几百米、全程见天）加上厘米级定位与真北航向，
把「感知要理解整个场景」简化成了「感知只要看前面有没有东西」——问题比乘用车
简单一个数量级。**因此不追 BEV / 占用网络 / 端到端**：那类方案需 100 TOPS 级
算力与大量标注数据，而我们的先验已经把问题简化掉了。

### 下位机：保持 ESP32-S3

下位机对主控的硬指标全部满足——算力（已有 1 kHz 级控制环的实测经验）、
TWAI 经典 CAN、3 路 UART（日志 / IMU / 舵机各一路，正好用满）、模组自带
8 MB PSRAM（黑匣子 480 KB）。故**不换主控**。

被否的替代：ESP32-P4（无官方模组、生态资料少一个数量级、无内置无线）；
STM32G474（要重画板，且黑匣子需外挂 flash）。

> **超声波已从方案中移除**（下位机上不再有任何环境传感器）——RDK 断链期间
> 控制域无本地感知，影响见「安全与失效 · RDK 断链行为」。

### 无线调试通道：只在调试期开

下位机需要无线通道看波形、改参数。**原则：调试期开、运行期关**，做到「开与
不开对控制效果无可观测差别」——隔离措施（任务绑定、发送解耦、内存纪律）见
[下位机设计方案](天鹅座-ESP32S3_下位机设计方案.md)，配置见参数 4.8。

- **判据**：节拍 max 抖动 < 100 µs（周期 5%），且开 / 关 WiFi 对照组的姿态与
  力矩曲线无统计差别
- **与遥控共存**（同频段是物理冲突，只能缓解）：NRF 改频 + 双射频降功率 +
  天线极化正交，配置见参数 4.4 / 4.8
- **备选**（软件隔离实测不达标时）：外挂 ESP32-C3 做网络协处理器，主控不跑
  协议栈——唯一能做到「时序也完全不受影响」的硬件隔离

## 各端职责与硬约束

> 具体数值、寄存器、配置项见[参数与配置](天鹅座-参数与配置.md)。本节只列
> **改了会牵连别处**的硬约束。

### STM32G431 电驱

双电机 FOC：动量轮走力矩环（指令来自 ESP32 平衡环），摩擦驱动走速度环。

- **功率级按相电流 100 A 设计**（不是 60 A）——由 θ_rec = 3° 推出的硬指标
- 分流电阻必须开尔文连接（0.25 mΩ）；DRV8301 增益 40 V/V（对称满量程约
  ±135 A，见参数 3.2）；小电流段精度差是预期行为，**不得据此判定电流环故障**
- VDS 过流阈值与 OCP 模式必须配置（**锁存关断**档，保证过流会拉 nFAULT 进 BKIN
  链）；母线电压超阈值时软件限制回馈
- 母线与功率器件耐压 ≥ 50 V + TVS 钳位（飞轮卸载会回灌能量）
- **分阶段上电**（只焊 MCU → 加 DRV8301 不焊 MOSFET → 限流电源带小电机 →
  台架逐级升流 → 才接真飞轮），把硬件问题与控制问题彻底分离

### ESP32-S3 下位机

平衡环、运动控制、状态机、指令仲裁。IMU 直挂本地。

板级设计与固件架构以[下位机设计方案](天鹅座-ESP32S3_下位机设计方案.md)为准，
本节只列**改了会牵连别处**的硬约束：

- **平衡环算法分两阶段**：前期串级 PID 验证，后期 LQR 定型；切换不预设 M 期，
  按实测与模型就绪判断；LQR 最低范围是平衡环（见「控制算法」）
- **3 路 UART 已用满**（UART0 日志 / UART1 IMU / UART2 舵机），不要再往上加
  设备——确需扩展时先看 I2C 或 SPI（分配见参数 4.7）
- **黑匣子不是可选项**——只要做「先尝试保平衡」的分级降级，失败那一刻就必须
  留下数据
- 遥控器是按需上电的控制手段，**不纳入安全设计**

### RDK X5 决策端

承担感知与路径规划，**只输出「目标速度 + 目标航向」**（20 ~ 50 Hz），进控制域
前由 ESP32 做仲裁与平滑。输出永远是建议，掉线不影响控制回路。

| 传感器 | 选型 | 说明 |
| --- | --- | --- |
| **GNSS 双天线** | 和芯星通 UM982（双天线定向 + 星基 PPP） | 导航域**绝对位置与真北航向的唯一来源** |
| 双目相机 | RDK GS130WI（全局快门、基线 70 mm、**板载 ICM-42688-P IMU**） | **局部 costmap 与避障的主传感器**，有效距离待实测 |
| 激光雷达 | 乐动 D800 / STL27L（DTOF，60 Klux，360°） | **后方 / 侧后方补盲**、空隙宽度第二来源、多回波玻璃检测；补双目无纹理失效 |

- **局部 costmap 半径受双目可信距离限制**（推算 5 ~ 8 m，待实测），不是
  「十余米」
- **坐标系统一最先做**：WGS84 → ENU 局部平面 → `map` / `odom` / `base_link`
- **地理原点一经确定不得更改**——卫星图配准、航点坐标、历史日志全依赖它
- **路径曲率上限随速度变化**（`κ ≤ g·tan20°/v²`），禁止「停-转-走」避障
  ——每次低速启停都在消耗飞轮动量（包线仅 ±3°），频繁停走会让飞轮饱和
- **导航域 IMU 用 GS130WI 板载的 ICM-42688-P**，不用经 CAN 转发的 HWT606
  （后者要过 TWAI → 收发器 → 总线仲裁 → TCAN4550 SPI 转 CAN → Python 桥接，
  时间戳抖动是毫秒级）

## 安全与失效

安全兜底分两层：

- **第一层完全独立于软件**——DRV8301 自带的 VDS 过流保护与 OCP，加上 TIM1/TIM8 的
  BKIN 硬件刹车（nFAULT → 封锁 PWM，约 100 ns）。不受任何链路、任何 MCU 状态影响
- **第二层是急停，走 CAN 指令**——只依赖 **CAN 总线与 STM32 正常工作**。这是本设计
  **已知且接受的边界**：车上不设任何物理急停按钮，也不再有独立于 MCU 的人工兜底

分级降级：

| 等级 | 触发 | 行为 |
| --- | --- | --- |
| **正常** | — | 平衡 + 行驶 |
| **可恢复** | 倾角 < 8° | 正常纠偏，飞轮卸载环工作 |
| **饱和** | 飞轮转速进入 ±90% 上限 | 强制进入卸载模式，牺牲平衡精度换回动量 |
| **软停车** | RDK 指令 / 电池低压截止 | **优先保持平衡 + 最大制动减速到 0**，期间持续判据「控制域是否可信」 |
| **认输** | 倾角 > θ_max 且 1 s 未收敛；或车速 > 3 km/h 时失稳 | 关断三相桥、飞轮自由滑行、舵机回中、蜂鸣器 |

⚠️ **最后一级就是「认输」**——支撑杆改为被动（人工操作）后，车上没有能自动接住
车体的装置，失稳即倒地。

**判据「控制域可信」**（软停车能否保住平衡的前提）：IMU 数据在合理范围 +
CAN 心跳正常 + 无故障标志 + 倾角在包线内。任何一条不满足，直接跳到「认输」。

**RDK 断链行为**（RDK 不在闭环内，必须显式设计）：

- ESP32 维护最近一次收到 RDK 指令的时间戳，超时 > 200 ms 进入原地平衡 / 缓停
- ⚠️ **控制域无本地环境感知**（超声波移除后）：断链期间车不知道前方有无障碍，
  避险完全依赖「停车」这个动作本身——**这是删除超声波后留下的已知缺口**
- 急停由总线 0x001 帧发起（RDK / 上位机 / 遥控器均可），STM32 收到后
  **自行完成封锁**，不依赖发起方后续参与——发完帧就断链也不影响关断结果
- RDK 重启、传感器掉线均不触发控制域状态变化

**急停走 CAN 指令，车上不设物理按钮**：

| 项 | 说明 |
| --- | --- |
| 触发 | CAN **0x001** 帧（ID 最小、优先级最高）；RDK / 上位机 / 遥控器均可发起 |
| 执行 | STM32 收到即**封锁 TIM1/TIM8 输出 + 拉低 EN_GATE**，功率级失力 |
| 行为 | 立即关断，**不走分级降级**、不尝试保平衡，接受倒地 |
| 依赖边界 | **CAN 总线 + STM32 正常工作** |

不设物理按钮的原因：**行驶中（1 ~ 4 m/s）人追不上车、够不着按**，物理按钮恰恰覆盖
不到最需要急停的场景；它唯一能覆盖的「人已在车边」场景，可由上位机经 RDK
发一帧 CAN 等效替代。

⚠️ 代价明说：**CAN 总线断线时急停完全失效**，只剩拔电池——独立于 MCU 的人工
兜底（物理按钮）没有了。

**机械与电气保护**：

- 飞轮防护罩按「承受轴或安装失效时飞轮的重量」设计。飞轮轮缘线速度仅
  14 m/s，比爆裂包容标准低一个数量级，**无需按爆裂包容设计**
- **不装机械刹车**——制动由摩擦驱动的电气制动承担；急停场景接受倒地
- 海绵垫包覆易磕碰处；电池主回路熔断器；STM32 独立看门狗 + ESP32 任务看门狗
- **电池低压保护两级、软降载而非硬切**（3.5 V/片起降载 → 3.2 V/片限流到零）。
  6S 航模锂电不带 BMS，**截止点贴太近会误触发欠压保护反而造成失控**
- 断电后飞轮**不做主动制动**（倒地的车若被电气制动，反作用力矩会让它翻滚），
  改自然减速；**落地后等 2 分钟再靠近**

**起立与停机**：

- **控制域先启动，不等 RDK**：上电自检 → 动量轮启动 → 平衡环接管。RDK 起得慢
  （数十秒）不影响任何一步——它只是建议源
- 起立：**被动支撑杆撑住车体** → 上电自检（不通过先重试，**3 次失败蜂鸣器报警**）
  → 动量轮启动 → 平衡环接管、保持平衡 → **人工踢开支撑杆** → 正常运行。
  固件**不区分**支撑杆是否已被踢开（没有传感器，也不需要区分）；无指令时速度环
  目标为 **0**，原地保持不动
- 停机：**就是断电，没有中间态**——动量轮运行中不许停（它是唯一的平衡执行器），
  不存在「先退出平衡再停机」这种流程；断电后车由人手或支撑杆接住（飞轮不主动制动，
  见「机械与电气保护」）

## 验证计划

每期只验一件事，不通过不进下一期。

| 期 | 对象 | 验什么 |
| --- | --- | --- |
| **M0** | 电驱板 + 平衡电机（**不装车**） | FOC 换相、电流环、100 A 尖峰波形、温升、母线回灌时电压抬升多少 |
| **M1** | 装车 + 悬挂（吊住车把与座垫，限制最大倾角） | **PID** 方向、增益量级、IMU 延迟实测；记录阶跃响应供模型辨识 |
| **M2** | 落地，支撑杆（被动）撑住 | **PID 静态站立**——第一个真正的里程碑 |
| **M3** | 加摩擦驱动 | 直线行驶、速度环、摩擦驱动打滑率实测（算法按实测决定） |
| **M4** | 加转向 | 增益调度标定，找出动量轮 ↔ 转向权重的实际交叉速度（算法按实测决定） |
| **M5** | 加 RDK | 感知接入（含**双目有效测距实测**、**激光雷达户外实测**、曝光 / 置信度调优、BPU 语义检测）、桥接链路（目标速度 / 航向 → CAN → ESP32） |
| **N1** | 加 GNSS（**天线先架好，不装车**） | 坐标转换、真北航向精度、PPP 收敛时间实测 |
| **N2** | 小范围遥控行驶 | 双 EKF 融合质量、GNSS 失锁时的降级表现 |
| **N3** | 卫星图转 costmap + 标定点扫描 | 规划路径是否沿路、是否穿越禁区 |
| **N4** | 完整 Nav2 航点任务 | **陌生园区环境端到端自主导航**（验收第三层） |

> 接入前继续用 PID，接入后保留回退路径。M3/M4 不预设算法。

## 技术约定

**元约定**（文档与架构治理，变更需先更新本文档）：

1. 本文件是项目技术决策的唯一事实源；技术方案变更先改本文档再实施
2. **域隔离**：RDK X5 的输出永远是建议，不得进入控制回路；控制域断链行为
   必须显式设计
3. 新增 CAN 帧必须落入既有 ID 分配段（安全 / 控制 / 电驱状态 / 规划 /
   整车状态 / 保护），不得随意扩展
4. 传感器接入：实时控制输入（IMU）直连 ESP32-S3；感知 / 导航类传感器
   （GNSS、双目、激光雷达）接 RDK X5
5. 电驱板设计以[电驱设计方案](天鹅座-STM32G431RBT6_双电机FOC设计方案.md)为准，
   本文档不重复其内容
6. 下位机的板级设计与固件架构以[下位机设计方案](天鹅座-ESP32S3_下位机设计方案.md)
   为准，本文档不重复其内容
7. **安全兜底分层**：DRV8301 的 VDS/OCP 与 BKIN 硬件刹车独立于软件，不受任何
   链路影响；**急停走 CAN 0x001 指令**，依赖 CAN 总线与 STM32 正常工作。触发源
   （RDK / 上位机 / 遥控器）只是发起者，**不是安全链的一环**，其失效不影响第一层
