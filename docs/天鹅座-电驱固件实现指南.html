1电驱端全景

电驱板是控制域的执行末端：它不决定车怎么平衡，只负责把 ESP32 下发的力矩/速度指令变成三相电流，并在一切出错时最快地关掉功率级。

双电机分工

电机定时器DRV8301SPI 总线编码器控制环
电机 1 · 动量轮TIM8（PC6~PC8 / PC10~PC12）DRV8301-1（nFAULT→PA15）SPI1MT6816-1力矩环（指令来自 ESP32 平衡环）
电机 2 · 摩擦驱动TIM1（PA8~PA10 / PB13~PB15）DRV8301-2（nFAULT→PD2）SPI3MT6816-2速度环
注意FOC 嵌套关系：电驱端只跑电流环（20 kHz）；力矩/速度环在 ESP32 上（200~500 Hz）。STM32 收到的是「力矩/速度指令」，换算成 Iq 目标后由电流环跟踪。不要在 STM32 上再搭一层速度环。

信号流（单电机电流环）

电流环一个控制周期（50 µs）内的完整链路。虚线以上是软件，以下是功率级；ADC 注入由 PWM 顶点触发，所以采样、计算、输出天然同相。

时钟树

RCC

main.c · SystemClock_Config()
HSE 8 MHz → PLLM /2 → PLLN ×85 → PLLR /2 → SYSCLK 170 MHz
PLL 输入 4 MHz 落在 2.66~16 MHz 内，VCO 340 MHz 在 96~344 MHz 内。HCLK / APB1 / APB2 均 /1。
PWR_REGULATOR_VOLTAGE_SCALE1_BOOST + FLASH_LATENCY_4
不切 Boost 跑不到 170 MHz；漏配 Flash 等待周期会跑飞。两者都必须在 PLL 配置之前/之后按正确顺序执行（生成的代码已保证）。
CSS 使能
HSE 失效硬件自动切 HSI16，但系统时基降为 1/10——FOC 全部失准，必须在 RCC 中断里受控停机（第 6 节）。
HSE_VALUE = 8000000（hal_conf.h）
G4 HAL 默认写的是 NUCLEO 的 24 MHz，不改则串口波特率、定时周期、HAL_Delay 全部偏 3 倍。已改好。
判据：HAL_RCC_GetSysClockFreq() 上电打印应为 170000000。这是骨架里第一个自检。

TIM1 / TIM8 —— 双电机 PWM 与 ADC 触发

TIM1（电机 2） / TIM8（电机 1）

tim.c · MX_TIM1_Init() / MX_TIM8_Init()
中心对齐 CENTERALIGNED1 · ARR = 4249 · PSC = 0 → 20 kHz
170 MHz / (4249+1) / 2 = 20 kHz。中心对齐是为了让「下桥全开窗口」以三角波顶点为中心——电流采样点就在那里。
CH1~CH3 初始 Pulse = 0，MOE 不开（HAL_TIM_PWM_Start 之前没有输出）
上电即 0% 占空比；六个 PWM 脚在 MOE=0 时由定时器拉低（OSSI/OSSR 已配 Disable，空闲上下桥全关）。
TRGO2 = TIM_TRGO2_OC5REF · CH5 无引脚 · CCR5 = 4200
这是采样时刻的机关：中心对齐下更新事件每周期出现两次（顶点与谷底），直接拿 UEV 当触发会采到谷底（三相上桥全开、低侧无电流）的假值。OC5REF 只在上数匹配 4200 时出一次上升沿——顶点前 49 个计数（≈0.29 µs），EPWM 窗口中部。ADC1 ← TIM8_TRGO2、ADC2 ← TIM1_TRGO2 已配好。
Break：极性 LOW（nFAULT 低有效）· 滤波 BKF=0011（8×fDTS ≈ 47 ns）· AOE = Disable · BKLOCK（LockLevel_3）· OSSI/OSSR = Disable
nFAULT 到封锁 PWM 约 100 ns，纯硬件、不经过代码。AOE 关掉是禁止故障后自动恢复；BKLOCK 锁存，恢复必须软件显式清。滤波档位刻意没用 fDTS 大分频（可达 µs 级，等于废掉刹车）。
死区 DeadTime = 0
死区由 DRV8301 的 DTC 电阻承担（50~500 ns 可调）；TIM 侧再加会与其叠加，低速电流畸变。台架第 1 阶段用示波器实测总算账。

ADC1 / ADC2 —— 注入测电流，规则测慢量

ADC1 ↔ 电机 1 · ADC2 ↔ 电机 2

adc.c · MX_ADC1_Init() / MX_ADC2_Init()
时钟：SYSCLK /4 → 42.5 MHz（ADC_CLOCK_SYNC_PCLK_DIV4）
G4 双 ADC 同时工作时内核时钟上限 52 MHz——170 MHz 下 /4 是唯一合规档，/1、/2 都超。改时钟树时这条最容易连带损坏。
注入组：2 通道、采样 6.5 cycles、上升沿触发
6.5 + 12.5 = 19 cycles ≈ 0.45 µs/通道；两通道合计 ~0.9 µs，装进低侧窗口预算（总窗口约 2.5 µs @95% 调制比）。
规则组（ADC1）：IN8 VBUS → IN15 → IN12 → VREFINT（247.5 cycles）
软件触发、非连续。VREFINT 用来校正 VDDA 实际值（见第 10 节公式）——ADC 参考是 VDDA，磁珠后实际值有 ±1.5% 偏差，会进入每一个读数。
规则组（ADC2）：IN9（PC3，母线总电流预留）6.5 cycles
单通道。规则组与注入组并行；注入会抢占规则组，慢量读数被推迟没关系。
/* 注入读取（中断里） */
uint16_t ia = HAL_ADCEx_InjectedGetValue(&hadc1, ADC_INJECTED_RANK_1);
uint16_t ib = HAL_ADCEx_InjectedGetValue(&hadc1, ADC_INJECTED_RANK_2);
/* 规则组轮询（主循环）：每个通道单独 Start/GetValue，或一次 Start 后按序读 */
判据：EN_GATE 高、DC_CAL 高时注入两通道读数应 ≈2048（1.65 V）；EN_GATE 低时 SO 不输出，读数无意义。

FDCAN1 —— 500 kbps 经典帧

FDCAN

fdcan.c · MX_FDCAN1_Init()
时钟源 HSE 直连 8 MHz · BRP=1 · TSEG1=12 · TSEG2=3
16 tq × 125 ns = 2 µs → 500 kbps，采样点 81.25%，全程整数分频，精度只取决于晶振。
FrameFormat = FDCAN_FRAME_CLASSIC · AutoRetransmission = ENABLE
全总线经典帧（ESP32 TWAI 不支持 FD）；自动重传开启，急停/控制帧不因一次仲裁失败静默丢失。
滤波器：StdFiltersNbr = 0（尚未配）
生成代码里没有滤波器配置——骨架里必须自己配：至少放行 0x001（急停）与 0x010（控制指令），其余丢弃。参考写法：HAL_FDCAN_ConfigGlobalFilter() 全局拒绝非匹配帧 + HAL_FDCAN_ConfigFilter() 加两条 ID 过滤，然后 HAL_FDCAN_Start() 与 HAL_FDCAN_ActivateNotification()。
中断优先级 3（低于 BRK=0、ADC=1、EXTI=2）
CAN 接收相对不实时——控制环路不能被 CAN 中断抢占太多。

SPI1 / SPI3 —— 每条总线挂 DRV + 编码器

SPI1（电机 1 通道） / SPI3（电机 2 通道）

spi.c
Mode 3（CPOL=High / CPHA=2Edge）· /32 → 5.3125 MHz · 8 bit · 软 NSS
静态配置的是编码器常态档（MT6816 为 Mode 3，SCK ≤10 MHz）。DRV8301 是 Mode 1（nSCS 拉低时 SCLK 必须为低、下降沿采样），且速率 1~5 MHz——访问 DRV 前必须运行时切换 CR1（见下），用完切回。
切换序列（每次访问 DRV 前后）
等 BSY 清零 → SPE=0 → 写 CR1（CPOL/CPHA/BR）→ SPE=1；切换时两片 CS 都必须为高。CS 全由 GPIO 控制（NSS = SPI_NSS_SOFT，SSM/SSI 已在生成代码里）。
HAL 视角
HAL_SPI_Init 会写死模式——切换要么改 hspi1.Init.CLKPolarity/CLKPhase/BaudRatePrescaler 后调 HAL_SPI_Init() 重初始化，要么直接写 SPI1->CR1 位（更快但绕过 HAL）。骨架建议封装 spi_set_mode_drv() / spi_set_mode_enc() 两个函数。

USART2 · GPIO · NVIC

  • USART2 115200：调试日志 / 命令。printf 重定向（fputc）可选，注意别在中断里打大段日志。
  • GPIO 初始电平已按「安全侧」配好：EN_GATE / DC_CAL=Low（关断），四片选 + 三 LED=High（不选中、灭）。MX_GPIO_Init() 执行完功率级就是关断态。
  • NVIC 层次：TIM1_BRK / TIM8_BRK=0 → ADC1_2=1 → EXTI4 / EXTI15_10=2 → FDCAN1_IT0=3 → SysTick=15。BRK 最高是因为它只做「补封 + 拉 EN_GATE + 置标志」，必须最快。

IWDG —— CubeMX 生成，启动延后到序列末

窗口看门狗

iwdg.c · MX_IWDG_Init()（不生成自动调用）
参数：LSI 32 kHz / 32 → 窗口 20~40 ms（Window=20 / Reload=40），喂狗取 30 ms 中段
窗口模式连「程序跑飞后仍定时喂狗」这类假活也能抓——喂早喂晚都复位。
核心机关：控制「谁在什么时候调 MX_IWDG_Init()」
G4 HAL 的 HAL_IWDG_Init 内部即写启动键（__HAL_IWDG_START），Init 即启动、无独立 Start API，CubeMX 面板也没有「只配置不启动」档——所以调用时机就是狗上岗时机。若让 main() 自动调用，上电序列（等 nFAULT + SPI 校验 + DC_CAL）超 40 ms 就被咬。
做法：Advanced Settings 取消 IWDG 的 Generate Function Call
CubeMX 里 IWDG 正常配 P32/W20/R40（生成 iwdg.c/h；hal_conf 宏与 uvprojx 注册都由 CubeMX 自动维护）；Project Manager → Advanced Settings → IWDG 行取消勾选 Generate Function Call——main() 不再自动调用，由你在序列末尾显式调用 MX_IWDG_Init()（第 5 节第 10 步）。该设置保存在 .ioc，重新生成持久生效。
唯一纪律：勿把 Generate Function Call 勾回去——勾回即恢复「初始化即放狗」。

5上电序列（app_init 逐步实现）

方案 3.2 第 7 条固化的顺序，不可换——每一步失败就停在该步，用 LED 慢闪报错，不上桥。这是「把硬件问题与控制问题分离」的固件侧对应物。

  1. 复位原因记录

    读 RCC->CSR：IWDGRSTF / PORRSTF / SFTRSTF / PINRSTF。要跨复位保留的写进备份寄存器：HAL_PWR_EnableBkUpAccess() 后写 RTC->BKP0R。然后清 RCC->CSR。

    注意：VBAT 接 3.3 V、无电池——BKP 只在同一电源周期内有效；掉电原因本身从 CSR 读即可，不需要 BKP。

  2. 时钟自检

    HAL_RCC_GetSysClockFreq() == 170000000。不对就停——时钟不对跑 FOC 全是错的。

  3. ADC 校准

    两路各做一次 HAL_ADCEx_Calibration_Start(&hadc1, ADC_SINGLE_ENDED)，要在使能 ADC 之前、上电一次即可。规则组和注入组共用一次校准。

  4. 调试冻结位

    SET_BIT(DBGMCU->APB2FZ, DBGMCU_APB2FZ_DBG_TIM1_STOP | DBGMCU_APB2FZ_DBG_TIM8_STOP)，再加 TIM4（泄放）与 IWDG（DBGMCU->APB1FZR1 对应位）。不配的后果：调试器一停 CPU，PWM 还在跑、电机突然转；单步超 40 ms 会被狗咬复位。

    用代码配而不是 Keil 的 dbgconf——DebugConfig/ 在 .gitignore 里，不入库。

  5. SPI 总线与电机结构初始化

    两路片选置高；spi_bus_init() 设成编码器常态档（Mode 3 / 5.3 MHz）；电机状态清零（零点、Iq 目标、故障标志）。

  6. 拉高 EN_GATE，等两片 nFAULT 释放

    HAL_GPIO_WritePin(EN_GATE…)SET，然后轮询 GPIOA->IDR bit15 与 GPIOD->IDR bit2 都为高。引脚是 AF 模式（BKIN），但 IDR 在 AF 输入下照样反映电平，直接读即可。超时（20~50 ms 量级）判失败。

    为什么等：EN_GATE 拉高后芯片约 5~10 ms SPI 才就绪；nFAULT 变高表示可接收 PWM。EN_GATE 低电平期间 SPI 不可用（内部稳压器休眠）。

  7. DRV8301 配置并读回校验

    两片逐个：SPI 切 DRV 模式 → 写 CTRL1（OC_MODE=锁存关断、增益 40 V/V、6-PWM 模式、驱动电流）→ 写 CTRL2 → 读回比对 → 切回编码器模式。先配再开 PWM，任何情况下不例外。寄存器细节见第 8 节。

  8. DC_CAL 读零点

    PB10 拉高 → 注入两通道读数应 ≈2048（±5% 起步）→ 存到电机结构 → PB10 拉低。

    为什么此时能读：DC_CAL 高时 SO 输出固定为 REF 电平（1.65 V）；必须在 EN_GATE 之后——EN_GATE 才使能采样放大器。偏离过多说明 DRV 或采样链有问题，停。

    此时 MOE=0 无 PWM 输出，但 TIM 计数照跑、TRGO2 照常触发注入转换——零点读数不需要软件触发旁路。这要求 TIM 已经在跑（第 9 步前先 HAL_TIM_Base_Start）。

  9. 启动计时与中断，保持待命

    TIM1/TIM8 HAL_TIM_PWM_Start（MOE 仍 0，输出关）→ 使能 ADC 注入中断（HAL_ADCEx_InjectedStart_IT）→ 状态机停在 MOT_IDLE。电机只在收到 CAN 使能指令后才开环。

  10. 最后：启动 IWDG

    调用 MX_IWDG_Init()——CubeMX 生成在 iwdg.c：写 P32 / Window=20 / Reload=40 后调 HAL_IWDG_Init（内部即启动）。它只在这里被调用，是因为 Advanced Settings 取消了它的 Generate Function Call（第 3 节）。此后主循环每 30 ms 喂一次。

序列判据：① 每步失败有独立的 LED 慢闪节拍（数闪烁次数定位步骤）；② 全程无复位（IWDG 未启动，不应被咬）；③ 结束时 EN_GATE 高、nFAULT 高、MOE=0、注入零点已存。

6保护链

保护链必须先于控制环写——它不依赖 FOC 的任何状态，写完就能验。

BKIN 中断：交叉映射（别凭直觉）

中断来源硬件已封锁软件要做
TIM1_BRK_TIM15_IRQHandler → HAL_TIMEx_BreakCallback(&htim1)PA15 ← DRV8301-1 nFAULT = 电机 1 故障TIM1（电机 2 桥）补封 TIM8 的 MOE（故障片自己的桥）、拉低 EN_GATE、置 FAULT_M1_BKIN
TIM8_BRK_IRQHandler → HAL_TIMEx_BreakCallback(&htim8)PD2 ← DRV8301-2 nFAULT = 电机 2 故障TIM8（电机 1 桥）补封 TIM1、拉低 EN_GATE、置 FAULT_M2_BKIN
 
/* 回调实现要点（因在中断上下文，只做三件事） */
void HAL_TIMEx_BreakCallback(TIM_HandleTypeDef *htim)
{
    if (htim == &htim1) {                    /* 电机1 故障 */
        __HAL_TIM_MOE_DISABLE(&htim8);       /* 补封电机1自己的桥 */
        g_fault |= FAULT_M1_BKIN;
    } else if (htim == &htim8) {             /* 电机2 故障 */
        __HAL_TIM_MOE_DISABLE(&htim1);
        g_fault |= FAULT_M2_BKIN;
    }
    HAL_GPIO_WritePin(EN_GATE_PORT, EN_GATE_PIN, GPIO_PIN_RESET);
    /* 不读 DRV 状态、不碰 SPI——诊断放主循环（总线与编码器共用） */
}

nOCTW 与 CSS

  • EXTI（HAL_GPIO_EXTI_Callback）：GPIO_PIN_13 → FAULT_OTW1（DRV8301-1）；GPIO_PIN_4 → FAULT_OTW2。两片独立接入，中断即知哪片预警。
  • CSS（HAL_RCC_CSSCallback）：时基已坏，直接走与软急停相同的终点——封 MOE + 拉 EN_GATE，置 FAULT_CSS，不尝试闭环。
  • 软急停（CAN 0x001，主循环解析）：同样「封 TIM1/TIM8 MOE + 拉 EN_GATE」，不走分级降级、不尝试保平衡。

故障恢复链（仅主循环做）

  1. 读 TIM1/TIM8 的 BIF 并清除；
  2. 优先用 SPI 写 DRV 的 GATE_RESET 位清 DRV 故障（访问前后切总线模式；不扰动配置、绕开 EN_GATE 10~20 µs 复位禁区）。GVDD_OV 例外——只能 >20 µs 的 EN_GATE 复位或断电；
  3. 确认 nFAULT 已释放；
  4. （若期间经历完全复位则重写 DRV 配置）；
  5. 置 MOE 恢复输出。
坑BKIN 中断里读 DRV 状态会把 SPI 拖进中断，与 20 kHz 电流环抢总线（编码器同一条线），直接导致控制环时序崩溃——诊断必须在主循环，用标志位排队。

7电流环与 FOC

采样时机（已在硬件配好，理解即可）

中心对齐 + PWM1 时，三角波顶点处三相下桥全开，分流电阻上流过的才是真正的相电流。TRGO2（OC5REF @ CCR5=4200）在顶点前 0.29 µs 触发注入转换——ADC 采样（~0.45 µs ×2）恰落在顶点附近窗口中部。你在中断里读到的就是有效值，不用做任何时序处理。

电流换算

/* 每 LSB 的电流（3.3V 参考） */
V_LSB  = VDDA_real / 4095;                /* ≈ 0.806 mV */
I_PER_LSB = V_LSB / (G × Rs)              /* G=40 V/V, Rs=0.25 mΩ → ≈ 0.081 A/LSB */
I_a = (raw_ia - I_zero_ia) * I_PER_LSB;    /* I_zero 来自 DC_CAL（≈2048） */
/* 满量程：对称约 ±135 A——负向受 SO 线性下限 0.3V 限制。小电流段精度差是预期的。 */

变换与 SVPWM

  • Clarke（等幅值）：iα = ia，iβ = (ia + 2·ib)/√3（两相直接算，第三相 = −ia−ib）。
  • Park：id = iα·cosθ + iβ·sinθ，iq = −iα·sinθ + iβ·cosθ，θ 为电角度 = 机械角 × 极对数。极对数未定（M1_POLE_PAIRS），开环旋转法实测后再写死。
  • 反 Park：vα = vd·cosθ − vq·sinθ，vβ = vd·sinθ + vq·cosθ。
  • SVPWM：vα/vβ → 扇区与作用时间 → 三路占空比（七段式最常用）。输出 CCR = duty × (ARR + 1)；总线用中心对齐时直接写 TIM1->CCR1..3 / TIM8->CCR1..3（预装载）。
  • 调制比限 0.93（方案 3.2 第 10 条）——20 kHz、95% 占空比时低侧窗口只有 2.5 µs，装不下采样链预算，台架扫定。
  • PI 抗饱和：积分限幅到调制比上限对应电压；目标 Iq 来自 CAN 指令（力矩模式）或速度环输出（驱动模式由 ESP32 侧给）。

开环先行（M0 第一件事）

  1. 固定电角度、给定固定 Vd/Vq → 电机应锁在固定位置（开环强拖）；
  2. 缓慢旋转电角度（1 Hz 起步）→ 电机应平滑旋转，记录编码器读数验方向与极对数；
  3. 方向错/极对数不对：现象是开环能转、闭环立刻发散。

注入中断里的循环

void HAL_ADCEx_InjectedConvCpltCallback(ADC_HandleTypeDef *hadc)
{
    /* 1. 读两路相电流（hadc 判 ADC1/ADC2，各管一个电机） */
    /* 2. 读编码器角度（SPI，凭存储的电角度） */
    /* 3. Clarke → Park → PI → 反 Park → SVPWM → 写 CCR */
    /* 4. 故障标志置位时：MOE 封锁、不输出 */
}
坑20 kHz 中断里绝对不能做 SPI 阻塞读编码器（~1.6 µs 帧 + 模式检查），更不能读 DRV。编码器角度要提前在主循环/更高层缓存好电角度；中断只做数学与写 CCR。

8DRV8301 驱动

  • 帧格式：16 位 SPI 帧（bit15 = R/W，bit14~11 = 地址，bit10~0 = 数据）。读要两帧：第 N 帧发命令、第 N+1 帧收数据。
  • 必配项（CTRL1）：OC_MODE = OC latch shut down（默认逐周期限流不拉 nFAULT，BKIN 链会静默失效）、OC_ADJ_SET 按 RDS(on) × 跳闸电流查 SLOS719F Table 13、增益 40 V/V（默认 10，必须显式写）、6-PWM 模式、栅极驱动电流。
  • CTRL2：OCP 分档等——按 SLOS719F 配置。
  • 读回校验：写完逐个寄存器读回比对，不一致判失败（自检环节，不可省）。
  • 状态读取：FAULT 状态位（OC 状态位读后自清——读到立即存入变量）；nOCTW 原因（OTW/OC）同样放主循环。
  • 访问纪律：每次访问前切 Mode 1、片选拉低、16 位帧、片选拉高、切回 Mode 3。两片 CS 在切换期间必须都为高。

ID方向内容频率

主循环编排（app_main_loop）

  1. motor_poll：速度环/转速估计、编码器状态迁移；
  2. can_port_poll：状态帧上报调度（500 Hz 与低频帧）、指令断流检测（超时行为未定义——方案遗留，骨架只留回调，别拍脑袋实现）；
  3. 规则组轮询：VBUS（经 VREFINT 校正）、NTC、母线总电流 → 更新全局量；
  4. brake_chopper_poll：泄放假环（VBUS > V_brk 开通、低于回差关断；初期 bang-bang，确需 PWM 再用 10 kHz 档）；

  6. LED 心跳：LED_SYS 500 ms 翻转；DRV1/2 按使能状态；

11坑清单

坑 1PB15 配成 AF6（错）→ W 相下桥完全没有输出
机理PB15 是 TIM1_CH3N 的 AF4 引脚（PB13/PB14 才是 AF6），极易配错
对策tim.c 里已确认 GPIO_AF4_TIM1（MspPostInit）；改代码前对照第 2 节引脚表
坑 2把 Generate Function Call 勾回去 → 初始化即放狗，上电序列中途被咬复位
机理勾回后 main() 自动调用 MX_IWDG_Init()，而 HAL_IWDG_Init 内部即启动——狗在序列开始前就上岗
对策该勾选存于 .ioc、保持不勾；每次重新生成后 grep MX_IWDG_Init main.c 确认初始化序列里没有它
坑 3IWDG 在上电序列中复位循环
机理HAL_IWDG_Init 即启动；序列各步合计超 40 ms 就被咬
对策MX_IWDG_Init() 只在序列末调用；序列中不喂狗也不该喂
坑 4Break 滤波配成 fDTS 大分频 → 刹车响应变几十 µs，等于废掉硬件保护
机理BKF 档位与 fDTS 分频叠加，µs 级延迟让 100 ns 的设计目标落空
对策已配 BKF=0011（≈47 ns）；要改之前先算清楚 CKD 分频
坑 5DRV8301 复位脉冲落在 10~20 µs → 芯片失联，只能断电恢复
机理PVDD1 欠压瞬态禁区（SLOS719F §7.3.4.2）
对策复位用 <10 µs 或 >20 µs；能用 SPI 的 GATE_RESET 就不用 EN_GATE 复位
坑 6DC_CAL 在 EN_GATE 拉高前做 → 零点全是垃圾
机理EN_GATE 同时使能采样放大器；低电平期间 SO 不输出
对策序列固化：EN_GATE → 等 nFAULT → DC_CAL
坑 7DRV 寄存器写 40 V/V 前先开了 PWM
机理默认增益 10 V/V、默认 OCP 是逐周期限流；未配的 DRV 上桥等于保护链裸奔
对策先配 CTRL1/2 并读回校验，再置 MOE。此顺序写入方案 3.2 第 7 条
坑 8拿小电流段的精度差当电流环故障
机理0.25 mΩ × 40 V/V 下 1 A 只有 10 mV，噪声占比大——是分流方案的预期行为
对策只在 >10 A 段评估电流环；小电流段的问题交给外环
坑 9调试器停 CPU 时电机突然转
机理定时器不随 CPU 暂停；BKIN 只封 MOE，不封计数器
对策DBGMCU freeze 位（第 5 节第 4 步）必须配，走代码不走 dbgconf
坑 10中心对齐下 UEV 一周期触发两次注入采样
机理溢出与下溢都产生 UEV；谷底采到的是三相全上桥的偏置假值
对策已用 TRGO2 = OC5REF 方案（第 3 节）；不要改回 UEV 触发
