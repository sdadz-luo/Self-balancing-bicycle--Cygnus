# esp32s3-control —— 下位机（ESP32-S3）工作约定

控制域主控固件：平衡环、运动控制、状态机、指令仲裁。IMU（HWT606）直挂本地，
经 CAN（TWAI）与电驱板、上位机通信。工程尚未建立；
建立后沿用 ESP-IDF 标准布局（`main/` + `CMakeLists.txt` +
`sdkconfig.defaults`）。

## 构建

`idf.py build`、`idf.py flash monitor`。

## 改动禁区（改了会牵连别处）

- **平衡环节拍源不能用 `vTaskDelay`**——延时是 (0, n] 个 tick，会变成周期的地板；
  且 `CONFIG_FREERTOS_HZ` **要显式设 1000**（IDF 默认 100 Hz = 10 ms 粒度）。
  节拍源用 **GPTimer 中断 + 任务通知**，**不要用 esp_timer 的任务分发**（其任务
  优先级 22 < WiFi 23、同在 Core 0，开 WiFi 时会被推迟）
- **IMU 上电第一件事把 `BANDWIDTH` 改到 256 Hz**——带宽是硬上限、输出率次要；
  默认 20 Hz 带宽群延迟约 8 ms，2 ms 控制周期下不可接受
- **撑杆展开与平衡环退出必须原子发生**，否则飞轮会用数 N·m 的力矩去撬支撑杆
- **3 路 UART 已用满**（UART0 日志 / UART1 IMU / UART2 舵机）——不要再往上加
  设备；确需扩展先看 I2C 或 SPI（分配见参数 4.7）
- **控制任务与网络彻底解耦**——钉 **Core 1 + 优先级 19**（官方「≥19 不被内置
  任务抢占」以钉 Core 1 为前提）；控制任务里**只投队列、不做 socket 发送**；
  控制路径数据放内部 SRAM、**不放 PSRAM**（无线调试配置见参数 4.8）
- **控制任务永不阻塞**——`twai_transmit` 用 `ticks_to_wait = 0`（总线 Bus Off /
  仲裁失败时不能拖住 2 ms 的环）；输入（舵机状态、遥控、CAN 指令）走**最新快照**
  （双缓冲 + 序号）传入，不等任何跨核互斥量；黑匣子只投内部 SRAM 小队列，落
  PSRAM 由 Core 0 任务做
- **console 次级输出要关**——设 `CONFIG_ESP_CONSOLE_SECONDARY_NONE=y`：默认开着
  USB-Serial-JTAG，USB 插到「只供电不读口」的主机上会卡住启动（现象：开机即死、
  串口无输出）
- **舵机半双工要抑回显**——TX 经 1 kΩ、RX 直连同一根线，自己发的字节会收回来；
  用 `UART_MODE_RS485_HALF_DUPLEX` 或发送后丢弃回显。**位置回读是本项目的新
  路径**（原来的成功经验是只写不读、RX 悬空），M3 阶段先验它
- **黑匣子不是可选项**——只要做「先尝试保平衡」的分级降级，失败那一刻就必须
  留下数据（本地环形缓冲 30 s）
- **急停**：收到 CAN **0x001** 帧即封锁输出，不走分级降级、不尝试保平衡
- **NRF24L01 必须开启自动应答**（EN_AA 通道 0）——否则遥控器判定发送失败、
  按键位永不清除，会按 100 ms 周期反复触发；模块必须选 PA+LNA 版
- 遥控链路**两端速率必须一致**（建议同步改 250 kbps），改一端等于断链；
  链路短板在车端，调试时先怀疑本端
